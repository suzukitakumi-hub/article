# Phase3：戦略・構成設計

## このスキルを使うとき
- seo-articleワークフローのPhase3実行時
- 記事構成案の設計を依頼されたとき

## このスキルを使わないとき
- Phase2が未完了のとき

## 手順

### Step1：ペルソナの設定
{target_keyword}と{article_purpose}から、記事のターゲットペルソナを定義する。
BtoB記事の場合は「担当者」と「決裁者」の2つのペルソナを設定する。

各ペルソナに以下を明記：
- 役職・立場
- 業界・企業規模
- 抱えている課題（Phase1の4要素分析から導出）
- 検索に至った動機
- 情報収集行動（どこで調べるか、意思決定プロセス）
- 求める情報の優先順位
- 感情・心理（ポジティブ/ネガティブの両方）
- 記事を読んだ後に取ってほしい行動（CTA目標）

### Step2：記事構成案の設計
ユーザーの思考プロセス（認知→検討→決定）に沿った流れで構成を組む。
Phase2のギャップ分析で特定した差別化ポイントを反映する。

各見出しに対して以下を付記する：
- 使用するHTMLテンプレートのパーツ名（references/html-parts-guide.mdを参照）
- 盛り込む1次情報の候補（出典名、データの種類）
- 想定文字数
- カスタマージャーニーのどのフェーズ向けか（認知/検討/導入）

LLMO対策として、Q&A形式の見出しを適切な箇所に含める。
PAA収集結果から「〜とは？」形式の見出しに変換して組み込む。

### Step3：自社USP配置計画
references/tcj-company-profile.mdを参照し、記事の各セクションで自社の強みを自然に埋め込む計画を立てる。

USPは最低3つ以上を特定し、それぞれどのセクションに配置するかを明記する。
「なぜTCJなら解決できるのか」という根拠を、押し売りにならない形で配置する。

主訴求として以下を優先する：
- 企業ごとの業務要件に合わせたカスタマイズ日本語教育
- 特定技能の各分野に横展開できる教育設計
- 現場任せ/内製化が進む市場でも差別化できる実装支援

### Step4：1次情報・図表の実装計画
1次情報を以下の4分類で整理し、記事内の配置箇所を決定する。
- 社内データ・実績（アンケート結果、採用成功率、定着率など）
- 専門家の知見・独自メソッド（自社講師による独自の解説）
- 直接調査・公的データ（厚労省、出入国管理庁、業界レポートなど）
- 経験・体験・事例（導入事例、トラブル解決エピソード）

記事全体の3割以上を1次情報で構成することを目標とする。
画像を入れるべき箇所には <!-- 画像挿入箇所：{{画像の内容説明}} --> のプレースホルダーを入れる。

### Step5：本文文字数目標の定義（後方互換の追加要件）
既存の「記事全体の想定総文字数」に加えて、本文プレーンテキスト（タグ除去・空白除く）の目標文字数を明記する。

- 既定ルール：競合上位3記事の平均文字数以上を目標値にする
- 下限：原則5,000文字（速報性の高いトピックは3,500文字まで緩和可）
- 緩和する場合は、理由を1行で明記する

### Step6：Internal Link Planの設計（厳格クラスタ制約）
Phase4で内部リンクカードを迷わず実装できるよう、以下を出力する。

- 主クラスター（`references/topic-cluster-map.md` から1つ選定）
- 候補リンク（最大6件）
- 最終採用予定リンク（最大3件）
- 各リンクの採用理由（1行）
- 配置予定セクション（H2単位）

ルール：
- 同一クラスターを優先する
- クラスター外リンクは原則禁止（例外は本文で直接言及する論点がある場合のみ）
- URLは `references/internal-link-list.md` に存在するものだけを使う

### Step7：Claim-Evidence Mapの作成（必須）
Phase4で「根拠のない断定」を防ぐため、主要主張と根拠を事前に紐づける。

最低5件、以下の列を持つ表で出力する。
- 主張ID（C1, C2, ...）
- 主張内容（1文）
- 根拠種別（公的データ/一次情報/事例/社内実績）
- 出典（機関名・資料名・年）
- 配置予定見出し（H2/H3）

ルール：
- 「〜と言える」等の結論文には、必ず対応する根拠行を用意する
- 年次情報は可能な限り最新年を使い、古い場合は補足理由を添える
- Phase4で新規主張を追加した場合は、同時にMapへ追記する

### Step8：Phase3の出力フォーマット固定（rewrite_plan.md）
`mode=rewrite` の場合、Phase3の出力は `rewrite_plan.md` に以下の見出しを必ず含める。

```markdown
## Phase 3: 戦略・構成設計

### Internal Link Plan
- 主クラスター:
- 候補リンク（最大6）:
- 最終採用リンク（最大3）:
- 配置セクション（H2）:
- 採用理由:

### Claim-Evidence Map
| ID | 主張 | 根拠種別 | 出典 | 配置見出し |
|---|---|---|---|---|
```

必須ルール：
- 上記5項目は見出し名を変えずに出力する
- 「これから実施」「未実施」で終わらせない
- 空欄を残さない（候補が不足する場合は不足理由を明記）

## ゲート条件（すべて満たすまで次のPhaseに進めない）
- [ ] ペルソナ定義を出力済み（BtoBの場合は担当者＋決裁者の2名）
- [ ] 構成案（全H2/H3/H4と使用パーツ指定＋カスタマージャーニーフェーズ指定）を出力済み
- [ ] 自社USP配置計画（3つ以上のUSPと配置箇所）を出力済み
- [ ] 1次情報・図表の実装計画（4分類）を出力済み
- [ ] 記事全体の想定総文字数を明記済み
- [ ] 本文プレーンテキスト目標文字数（下限根拠つき）を明記済み
- [ ] Internal Link Plan（主クラスター、候補、配置、採用理由）を出力済み
- [ ] Claim-Evidence Map（主要主張5件以上）を出力済み
