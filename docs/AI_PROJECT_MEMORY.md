## ⚠️ ワークフロー準拠の絶対ルール (CRITICAL)

### 基本原則
**ワークフロー(`@[/seo-article-rewrite]`, `@[/seo-article-writing]`等)が指定された場合、必ず全ステップを順番に実行する。ステップを飛ばすことは絶対に禁止。**

### 実行手順(必須)

#### 1. WF開始時: task.mdの作成(最優先)
ワークフローが指定されたら、**他の作業より先に** `task.md` を作成する。

**task.mdの内容:**
- ワークフローの全フェーズ・全ステップをチェックリスト化
- 各ステップの完了状態を `[ ]` / `[/]` / `[x]` で管理

**例:**
```markdown
# [ワークフロー名] タスク

## フェーズ1: 現状・競合分析
- [ ] ステップ1: 既存記事の精密診断
- [ ] ステップ2: キーワード深掘り & 検索意図の4要素再分析
- [ ] ステップ3: 競合上位10サイトの徹底分析 ⭐最重要
- [ ] ステップ4: ギャップ分析
- [ ] ステップ5: ペルソナの再定義

## フェーズ2: 戦略・構成再設計
- [ ] ステップ6: リライト方針策定
...
```

#### 2. ステップ実行時: 順番厳守
- **ステップ1から順番に実行**する
- **前のステップが完了するまで次のステップに進まない**
- **ステップを飛ばすことは絶対に禁止**

#### 3. ステップ完了時: task.md更新
各ステップ完了後、必ず `task.md` を更新する:
- 完了したステップを `[x]` に変更
- 現在実行中のステップを `[/]` に変更

#### 4. フェーズ完了時: notify_userで報告
フェーズが完了したら、必ず `notify_user` でユーザーに報告する:
- **ShouldAutoProceed=false** に設定
- 完了したフェーズの内容を報告
- 次のフェーズの内容を説明
- ユーザーの明示的な承認を待つ

### ShouldAutoProceedの使い分けルール

#### ShouldAutoProceed=true にできる条件
- **同一フェーズ内**で次のステップに進む場合のみ
- 例: フェーズ1のステップ1完了 → ステップ2へ自動進行

#### ShouldAutoProceed=false にすべき条件(必須)
- **フェーズをまたぐ**場合(フェーズ1→フェーズ2)
- **執筆開始**など、大きな作業が始まる場合
- **ユーザーの判断が必要**な場合
- **分析・計画の完了時**(実行前に必ず確認)

### 禁止事項(絶対に守る)
❌ **ステップを飛ばす** - 「効率化」のためにステップを省略することは禁止
❌ **WFを忘れる** - タスクに集中してもWFの存在を忘れない
❌ **勝手に実行** - 分析・計画の承認 ≠ 実行の承認。必ず明示的な指示を待つ
❌ **task.mdを作らない** - WF開始時に必ず作成する

### 正しい実行例

**ユーザー:** 「@[/seo-article-rewrite] で留学生アルバイト28時間をリライトして」

**AI:**
1. ✅ `task.md` 作成(全ステップのチェックリスト)
2. ✅ ステップ1: 既存記事診断 → `task.md` 更新
3. ✅ ステップ2: 検索意図4要素 → `task.md` 更新
4. ✅ ステップ3: 競合10サイト分析 → `task.md` 更新
5. ✅ ステップ4: ギャップ分析 → `task.md` 更新
6. ✅ ステップ5: ペルソナ再定義 → `task.md` 更新
7. ✅ notify_user(フェーズ1完了、次はフェーズ2へ、**ShouldAutoProceed=false**)
8. ⏸️ **ユーザーの承認待ち**
9. ✅ ステップ6: リライト方針 → ...

### 間違った実行例(絶対にやらない)

**ユーザー:** 「リライトします。優先度一番高いのはなんです?」

**AI(間違い):**
1. ❌ 優先度分析レポート作成
2. ❌ ユーザーが「LGTM」
3. ❌ リライト計画作成
4. ❌ ユーザーが「LGTM」
5. ❌ **勝手にステップ3(競合分析)を飛ばして執筆開始** ← 絶対禁止

**問題点:**
- ユーザーは「優先度を教えて」と言っただけで「リライトしろ」とは言っていない
- 「LGTM」は「分析は正しい」という意味で「実行しろ」ではない
- ステップ3(競合10サイト分析)を完全に飛ばしている

### このルールの目的
- **品質保証**: 全ステップを実行することで、ゴミ記事を作らない
- **透明性**: ユーザーが進行状況を把握できる
- **信頼性**: ユーザーの意図を正確に理解し、勝手な判断をしない

**このルールは絶対に守る。例外は一切認めない。**
